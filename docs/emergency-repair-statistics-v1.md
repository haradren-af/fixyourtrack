# Аварийное восстановление: обмен с BikeHeatmap

Дополняет [сводку FIT v1](fit-session-summary-v1.md). Уже экспортированные аварийные GPX поддерживаются без повторного экспорта. Новая сводка, подменяющая исходные показания прибора, не создаётся.

## Точки GPX

Флаги находятся в `trkpt/extensions`, пространство имён `https://fixyourtrack.local/extensions/v1`; префикс произвольный. Значение флага — текст `true`.

- `reconstructed`: добавленная точка, её время интерполировано; показания датчиков и счётчик дистанции отсутствуют.
- `routeDistance`: расстояние **входящего ребра** берётся по координатам. Флаг ставится также на реальной точке, завершающей пропуск.
- `emergencyRepair`: точка относится к аварийному восстановлению. Сам по себе флаг не заменяет реальные показания дистанции.
- `repairAccepted`: существующий флаг принятого исправления.

Импортёр сохраняет исходные `fixtrack:distance`, скорость, каденс и другие показания. Пропущенное значение остаётся `null`. Граница `trkseg` разрывает ребро, без добавления расстояния через разрыв.

## Дистанция

Эталон — `getSampleDistances` и `getTrackStatistics` в `src/trackCore.js`.

1. Для каждого сегмента вычислить накопленную геометрию (haversine, R = 6371000 м).
2. Монотонные записанные счётчики имеют приоритет на записанных участках. Между редкими показаниями распределить прирост по времени (если оно корректно), иначе по индексу. До первого и после последнего показания использовать геометрию. Нулевой или немонотонный ряд счётчиков не заменяет геометрию всего сегмента.
3. Для входящего ребра с `routeDistance=true` использовать геометрическую длину **вместо** прироста счётчика. Остальные рёбра используют прирост из шага 2. Нельзя суммировать только рёбра с двумя показаниями счётчика: это теряет восстановленные километры.
4. Когда исходная FIT-сводка применима к сохранившимся записям без `reconstructed` (проверить привязку, сняв `routeDistance`), сохранить её поправку к исходному ряду счётчика: `исходный FIT totalDistance - исходная дистанция по точкам`. Если привязка не совпала, поправку не применять. Исходную сводку хранить неизменной.

Обычное исправление GPS с применимой FIT-сводкой сохраняет показатели прибора. Восстановленная дистанция помечается как расчётная.

## Время и средняя

После применённого аварийного восстановления экспорт содержит явную политику в `trk/extensions`:

```xml
<fixtrack:excludeFromAverageSpeed>true</fixtrack:excludeFromAverageSpeed>
```

Пространство имён прежнее, префикс произвольный. Маркер сохраняется при импорте, сохранении черновика и повторном экспорте. Пока исправление не применено, одно включение переключателя не меняет исходный трек. Отмена исправления восстанавливает предыдущий трек и его политику.

Heatmap сохраняет `excludeFromAverageSpeed: true` и исключает **всю поездку**, включая её дистанцию и длительность, из всех общих, годовых, месячных и отфильтрованных расчётов средней скорости. При этом километры, поездка, высота и карта участвуют в своих обычных итогах, а средняя отдельной поездки остаётся доступной с пояснением. При отсутствии допустимых поездок общая средняя неизвестна (`null`), а не ноль.

Для старых файлов без маркера исключение также определяется по признакам `emergencyRepair`, `reconstructed`, `routeDistance` либо сохранённому `averageSpeedBasis: "elapsed"`. Значение `false` не отменяет присутствующие признаки аварийного восстановления. Неизвестное пространство имён и маркер внутри `trkpt/extensions` не считаются политикой всего трека.

Если выборка содержит `reconstructed` либо входящее ребро `routeDistance` внутри сегмента, полное время в движении и время таймера неизвестны: оба значения `null`, источник `unavailable`. Нельзя классифицировать синтетические точки по порогу скорости, записывать время пропуска как измеренное движение или делить всю дистанцию на время только записанной части.

Для **суммарного времени** Heatmap использует у отмеченных поездок исходное записанное время, без учёта восстановленных участков: `totalMovingSeconds` из сохранённых FIT-сессий, при отсутствии — `totalTimerSeconds`. Это исходная статистика записи, поэтому её применение к сумме времени не зависит от привязки к исправленным точкам. Если FIT-сводки нет, отдельно сохраняется `recorded_moving_time`, оценённое только по реальным записанным рёбрам: синтетические точки, входящее `routeDistance`, разрывы сегментов и пропуски свыше 120 с не добавляют движение. API передаёт его как `recordedDurationSeconds`.

Исходное записанное время участвует в общем, годовом, месячном и отфильтрованном итоге времени. При наличии этого времени аварийная поездка не делает сумму «неполной». Полное время движения исправленной поездки остаётся неизвестным, и маркер продолжает исключать её из всех общих расчётов средней скорости.

Доступна **средняя за всё время**: восстановленная дистанция / elapsed time. Метаданные: `averageSpeedBasis: "elapsed"`, источник средней `estimate`. Интерфейс показывает `≈`, подпись «Средняя за всё время» и поясняет, что включены остановки. При отсутствии корректной положительной длительности средняя неизвестна. Для обычных треков прежние правила сохраняются.

Elapsed time — применимое исходное значение или разность крайних времён экспортированных точек. Обрезанному экспорту нельзя присваивать исходную длительность всей FIT-сессии. Интерполяция времени в пропуске не меняет его фактические границы.

## Совместимость

Синтетический пример: [GPX](examples/emergency-repair-v1.gpx), [ожидаемые показатели](examples/emergency-repair-v1.expected.json). Проверять импорт и повторный экспорт, сохранение короткой реальной записи между пропусками, отсутствие датчиков у добавленных точек, неприменимость старой сводки, смешение геометрии и счётчика без двойного счёта. Исправление уже сохранённой поездки должно менять только подтверждённые поля статистики, с резервной копией и сохранением исходного GPX.
