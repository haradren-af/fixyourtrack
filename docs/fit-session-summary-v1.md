# Сводка FIT в GPX: fixtrack activitySummary v1

Формат используется FixYourTrack и BikeHeatmap. [Рабочий пример GPX](examples/fit-session-summary-v1.gpx) содержит синтетические координаты и три точки; личные данные в пример не включены.

Сводка хранится в `gpx/trk/extensions`:

```xml
<fixtrack:activitySummary version="1" source="fit-session" encoding="json">
  { ... }
</fixtrack:activitySummary>
```

Пространство имён: `https://fixyourtrack.local/extensions/v1`. Префикс XML может отличаться. Внутри находится JSON, экранированный как обычный XML-текст. Расширение содержит исходные показатели, привязку к записи и вычисленные при экспорте флаги применимости. Оно не меняет время, координаты, число точек или счётчик дистанции. В версии 1 поддерживается ровно одно такое расширение на трек. Неизвестную версию, неверное пространство имён, дубликаты и некорректные данные потребитель игнорирует и использует явно обозначенные оценки.

## Исходные значения

`version` — число `1`, `source` — строка `fit-session`. `sessions` — массив исходных FIT-сессий. У каждой сессии есть `index`, соответствующий её позиции в массиве, и следующие поля:

| Поле JSON | Поле FIT | Единицы / формат |
| --- | --- | --- |
| `totalDistanceMeters` | `total_distance` | метры |
| `totalElapsedSeconds` | `total_elapsed_time` | секунды общего времени |
| `totalTimerSeconds` | `total_timer_time` | секунды работы таймера |
| `totalMovingSeconds` | `total_moving_time` | секунды движения |
| `averageSpeedMps` | `avg_speed` | метры в секунду |
| `startTime` | `start_time` | ISO 8601 UTC |
| `endTime` | `timestamp` | ISO 8601 UTC |

Неизвестное значение — JSON `null`. Числовые значения должны быть конечными и неотрицательными; настоящий ноль допустим. Время таймера не подставляется в исходное поле времени движения. Все поля исходной сессии сохраняются неизменными, даже если экспортируемый трек обрезан или даты перенесены.

## Привязка и проверка применимости

`binding` создаётся по исходным записям FIT и сохраняется без изменений:

| Поле | Смысл |
| --- | --- |
| `sampleCount` | число исходных записей, включая записи без GPS |
| `firstSampleTime` | первая известная дата точки, ISO UTC либо `null` |
| `timeDigest` | контрольная сумма относительного времени каждой точки |
| `distanceDigest` | контрольная сумма записанных значений дистанции |
| `segmentDigest` | контрольная сумма границ сегментов |
| `sessionIndex` | индекс единственной применимой ко всему треку сессии либо `null` |
| `sessionRanges` | упорядоченные диапазоны `{sessionIndex, firstSampleIndex, lastSampleIndex}`; индексы с нуля, обе границы включены |
| `mappingStatus` | `single-session`, `multi-session`, `ambiguous` либо `unmapped` |

Для файла с одной сессией она сопоставляется со всеми его записями. При нескольких сессиях каждая запись сопоставляется по времени с интервалом сессии. Пересекающиеся интервалы дают `ambiguous`, записи вне всех интервалов — `unmapped`. Если весь трек однозначно относится к одной из сессий, используется её индекс. Если трек объединяет несколько сессий, исходные сводки и диапазоны сохраняются, но итог первой сессии не используется как итог объединённой поездки: версия 1 показывает оценки. Это также не позволяет усреднить несколько несовместимых показателей прибора незаметно для пользователя.

Контрольные суммы: FNV-1a 32-bit, начальное значение `2166136261`, множитель `16777619`, восемь строчных шестнадцатеричных цифр. Для каждого элемента последовательно обрабатываются символы строки `JSON.stringify(value) + ';'`.

- Время: миллисекунды относительно первой известной даты; отсутствующее время — `null`.
- Дистанция: метры, округлённые как `Math.round(value * 1e6) / 1e6`; отсутствие — `null`.
- Сегменты: boolean, `true` у первой точки и у каждой точки с `segmentStart`.

Это проверка обычных изменений данных, а не цифровая подпись или проверка подлинности прибора. Координаты и флаг ремонта намеренно не участвуют: исправление GPS не меняет записанную дистанцию или время.

В JSON при экспорте дополнительно записывается `applicability: {distance, time, averageSpeed}`:

- `distance` требует совпадения числа точек, сегментов и записанных дистанций.
- `time` требует совпадения числа точек, сегментов и относительного времени, а также известной исходной и текущей первой даты.
- `averageSpeed` требует обоих совпадений.

Потребитель обязан повторно проверить эти флаги по фактическим точкам, а не доверять записанному `true`. При повторном экспорте привязка не заменяется привязкой изменённого трека. Иначе обрезанная поездка ошибочно получила бы применимую исходную среднюю.

Единый сдвиг дат сохраняет интервалы, поэтому длительности остаются применимыми. Актуальные начало и конец сессии вычисляются добавлением разницы текущей и исходной первой даты к исходным датам; сами исходные даты в `sessions` не изменяются. Изменение длительности снимает применимость времени и средней. Изменение дистанции снимает применимость дистанции и средней. Добавление/удаление записей снимает обе применимости. Если экспорт удаляет записи без восстановимых координат, применимость к полному FIT также снимается.

## Приоритет показателей

1. При применимой сводке использовать соответствующий записанный показатель прибора; средняя `averageSpeedMps` имеет приоритет.
2. Если средней нет, использовать дистанцию / соответствующее записанное время: движение, затем таймер, затем общее время. Обозначать эту среднюю как рассчитанную по записанным показателям.
3. Если нужного времени нет или сводка неприменима, оценивать движение по записанным точкам и явно обозначать среднюю и движение как оценки. Таймер при этом остаётся отдельным полем, а исходная сводка сохраняется для справки. Для [аварийного восстановления с интерполированным временем](emergency-repair-statistics-v1.md) полное время движения неизвестно; доступна отдельно подписанная средняя за всё время.

Для FIT от 09.10.2026 применимая сводка содержит `16778.22` м, `6863` с общего времени, `4413` с таймера, `4413` с движения и `3.801` м/с. Средняя отображается как **13,7 км/ч**; её нельзя заменить результатом оценки движения `4340` с.

Старый GPX без этого расширения не позволяет восстановить точное время таймера/движения прибора. Такой файл нужно заново экспортировать из FIT либо сопоставить с его исходным FIT, подтвердив совпадение всех записей времени и дистанции.
